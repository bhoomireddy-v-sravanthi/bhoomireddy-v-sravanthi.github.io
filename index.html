Spec

How I build an environment before the first test.

assume

The design is broken.

Somewhere there is a bug I have not found yet, so the plan comes before the code. I read the spec, list what must be proven, and only then decide which agents, sequences and checks the UVM environment needs.

assert

A rule gets written once.

Each rule lives in one place, as an assertion on the interface or a check in the scoreboard. The monitor observes, the scoreboard compares, and the driver stays out of the checking, so a failure points to one cause.

cover

Passing proves very little.

Suppose the environment only sends valid traffic and I am asked to test error responses. I add a sequence, set the configuration, and reuse the driver, monitor and scoreboard. Coverage shows what is still untried, and I keep going until every gap is explained.

Assume, assert and cover are also the three directives of the assertion language I write every day. UVM gives the structure, and knowing the design stays my job.
